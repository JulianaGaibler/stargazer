# 3D

Add a {@link MeshNode} to `engine.tree` and a {@link CameraNode3D} to view it, and the stage draws 3D content next to its 2D content. This page covers meshes, lights, shadows, glTF models, fog, pointer picking and HTML pinned to 3D nodes.

Each frame the stage draws the 3D nodes first, with depth testing, and then the 2D content on top. A stage with only 2D content runs only the 2D pipeline. The examples assume an `engine`, as in [Engine setup](/guides/setup).

## Basic usage

This example draws a lit cube. It adds a mesh, a light and a camera to the tree:

```ts
import {
  CameraNode3D,
  DirectionalLight3D,
  MeshNode,
  createBoxGeometry,
  quat,
  quatFromAxisAngle,
} from '@julianagaibler/stargazer'

const cube = new MeshNode(createBoxGeometry(1), {
  lit: true,
  pbr: true,
  color: [0.9, 0.3, 0.2, 1],
  metallicFactor: 0,
  roughnessFactor: 0.6,
})
cube.transform.setPosition(0, 0, -6)
engine.tree.add(cube)

const sun = new DirectionalLight3D({ intensity: 3 })
const tilt = quatFromAxisAngle(quat(), 1, 0, 0, -0.7)
sun.transform.setRotation(tilt.x, tilt.y, tilt.z, tilt.w)
engine.tree.add(sun)

const cam = new CameraNode3D()
cam.transform.setPosition(0, 1.5, 4)
engine.tree.add(cam)
```

A red cube appears, lit on its top and front faces. The camera looks down its local `-z` axis, so the cube sits 10 units in front of it. The light shines down its own `-z` axis, tilted toward the ground. The first {@link CameraNode3D} added to a stage becomes the current one.

A PBR material has `metallicFactor` `1` by default. A metal reflects its surroundings, and the engine has no environment to reflect, so a metal looks dark. Set `metallicFactor` to `0` for a colored non-metal, as this example does.

### Move and rotate nodes

Each 3D node has a `transform`, a {@link Transform3D} with a position, a rotation quaternion and a scale. Set them with `setPosition(x, y, z)`, `setRotation(x, y, z, w)` and `setScale(x, y, z)`. After you change the fields in place, call `transform.markDirty()`.

Use `add` to nest nodes. A child inherits its parent's world transform:

```ts
import { Node3D } from '@julianagaibler/stargazer'

const pivot = new Node3D()
pivot.transform.setPosition(0, 0, -6)
engine.tree.add(pivot)
pivot.add(cube) // the cube moves with the pivot
```

A plain {@link Node3D} has only a transform, so it works as a group.

### Animate a node

`Node3D.tween` interpolates position and scale, rotates along the shortest arc between rotations, and also takes `alpha`:

```ts
import { easings, quat, quatFromAxisAngle } from '@julianagaibler/stargazer'

await cube.tween(
  {
    rotation: quatFromAxisAngle(quat(), 0, 1, 0, Math.PI),
    position: { x: 2, y: 0, z: -6 },
  },
  { duration: 1, easing: easings.inOutCubic },
)
```

The cube turns half a revolution around `y` and slides to `x = 2` over one second, and the promise resolves when the tween ends. `quatFromAxisAngle` takes a unit-length axis and an angle in radians.

### Load a glTF model

{@link loadGltf} fetches a `.glb` or `.gltf` file, builds a tree of nodes, and decodes the textures before it resolves:

```ts
import { loadGltf } from '@julianagaibler/stargazer'

const model = await loadGltf('/models/robot.glb')
model.transform.setPosition(0, 0, -6)
engine.tree.add(model)
```

The returned root is a `Node3D`. The model's materials use the PBR program, its lights become light nodes, and its first animation plays in a loop. See [glTF details](#gltf-details) for what the loader reads.

### Add lights

Lights are nodes, so they move, nest and animate like other nodes. A {@link DirectionalLight3D} shines parallel rays along its local `-z` axis from any position. A {@link PointLight3D} shines in all directions from its position. A {@link SpotLight3D} shines a cone along its local `-z` axis.

This example adds a warm point light:

```ts
import { PointLight3D } from '@julianagaibler/stargazer'

const lamp = new PointLight3D({ color: [1, 0.8, 0.4], intensity: 5, range: 8 })
lamp.transform.setPosition(0, 2, -4)
engine.tree.add(lamp)
```

The cube gains a warm highlight on the side that faces the lamp. Light fades with distance, and `range` sets where it reaches zero. A scene with no light nodes uses one built-in directional light. See [Lighting](#lighting) for the details.

### Cast shadows

Set `shadowEnabled` on a light to make it cast shadows. PBR meshes receive them:

```ts
const sun = new DirectionalLight3D({
  intensity: 3,
  shadowEnabled: true,
  shadowMaxDistance: 20,
})
```

Meshes now cast shadows onto PBR surfaces. `shadowMaxDistance` limits how much of the scene one directional shadow map covers, which keeps nearby shadows sharp. See [Shadows](#shadows).

### Pick meshes with the pointer

Pointer events reach 3D nodes the same way they reach 2D nodes. Set `hitEnabled` and assign a handler, or use `bindPointer`:

```ts
cube.hitEnabled = true
cube.onPointerDown = () => select(cube)
```

On a press, the input system tests the 2D content first, because it draws on top. When no 2D node is hit, it casts a ray from the current 3D camera and picks the nearest mesh with `hitEnabled`. The test uses each mesh's bounding box, so a press near the corner of a sphere's box can hit the sphere.

## Advanced usage

The sections that follow cover coordinates, how 2D and 3D share the tree, cameras, materials, geometry, models, lights, shadows, fog, quality settings, picking, HTML overlays and debugging.

### Coordinate conventions

2D is y-down, in world units the size of a CSS pixel at zoom 1. 3D is right-handed and y-up, in meters, like glTF. A 3D camera looks down its local `-z` axis. Triangles wound counter-clockwise face the viewer, and back faces are culled.

The two spaces have separate coordinates. All 3D content draws behind all 2D content, so neither hides the other.

### 2D and 3D in one tree

2D and 3D nodes can be siblings, and you can nest one kind under the other. Nesting controls lifecycle and grouping. Destroying a parent destroys its children, and visibility passes down the whole tree regardless of kind.

Position follows the nearest ancestor of the same kind. A node builds its world transform from that ancestor and skips nodes of the other kind and `GroupNode`s in between. A `Node2D` under a `Node3D` follows its nearest 2D ancestor and draws on top of the 3D pass.

A stage draws into one render target that carries depth and stencil on a single attachment. That is how 3D content and 2D strokes that use the stencil, such as translucent multi-segment strokes, share a frame. The depth part exists only while a 3D camera is current and the tree holds 3D nodes. The stage releases it afterwards and the stencil stays. Hiding every mesh does not release it. A render target you allocate with `depthSampled`, such as the ambient occlusion G-buffer, carries depth only.

### Cameras and projection

A stage tracks one current 3D camera. Call [`makeCurrent()`](/module/camera/cameranode3d#makecurrent) to switch to another one, and set `enabled = false` to take one out of use. When the current camera is removed or disabled, the enabled camera with the highest `priority` takes over. `engine.currentCamera3D` is `null` until you add a camera.

The view is the inverse of the camera node's world transform, so parenting the camera to a moving node makes it follow that node. The projection comes from `fovY`, `near`, `far`, `focalDistance` and `projectionness`, which {@link CameraNode3D} documents with their defaults. The stage sets the aspect ratio from the canvas size every frame.

A camera blends continuously between orthographic (`projectionness` `0`) and perspective (`1`) projection. An object at `focalDistance` keeps its on-screen size during the blend, so the change reads as a change of projection and not a zoom. [`animateProjection`](/module/camera/cameranode3d#animateprojection) tweens the blend:

```ts
import { easings } from '@julianagaibler/stargazer'

cam.focalDistance = 6
await cam.animateProjection(0, { duration: 0.8, easing: easings.inOutCubic })
```

An object 6 units from the camera keeps its size while the view flattens to orthographic over 0.8 seconds.

### Materials

A {@link MeshMaterial} uses one of two shader programs, both drawn in the same pass. The flat program draws `{ lit, color }` with straight (not premultiplied) RGBA. A lit flat material is shaded by the built-in directional light and a constant ambient. The PBR program draws a material with `pbr: true`. It uses metallic-roughness shading with every light node and receives shadows, and glTF materials set `pbr: true`.

This material is a mostly metallic, slightly emissive wall with a normal map:

```ts
import {
  createQuadGeometry,
  createTexture,
  MeshNode,
} from '@julianagaibler/stargazer'

const normals = await createTexture(normalMapCanvas, { srgb: false })
const wall = new MeshNode(createQuadGeometry({ width: 4, height: 3 }), {
  lit: true,
  pbr: true,
  color: [0.8, 0.8, 0.85, 1],
  metallicFactor: 0.8,
  roughnessFactor: 0.4,
  emissiveFactor: [0.05, 0.02, 0],
  normalTex: normals,
  normalScale: 1.5,
})
```

Every PBR field is optional, so a plain `{ lit, color }` stays a valid material. The textures (`baseColorTex`, `metalRoughTex`, `normalTex`, `occlusionTex`, `emissiveTex`), `alphaMode`, `alphaCutoff`, `doubleSided`, `castShadow` and the other fields are documented with their defaults on {@link MeshMaterial}.

Set `castShadow: false` for geometry that should look like an overlay, such as a highlight lying on a surface. A mesh with `alphaMode: 'BLEND'` casts no shadow.

An unlit flat material takes a `baseColorTex` too. The flat program draws it unshaded, multiplied by `color`, and applies `alphaMode: 'MASK'` with a discard. Use it for finished artwork, where shading would make two copies of the same drawing at different angles look different.

`toonSteps` suits a scene drawn in flat color. Three or four steps keep a cylinder readable as a few blocks of tone. Only diffuse light is banded, and the specular highlight keeps its smooth falloff.

### Build geometry

A {@link MeshGeometry} is a plain object: positions, normals, optional `uvs` and `tangents`, and a 16-bit or 32-bit index list. You can build one by hand, or call a builder:

```ts
import {
  createDiscGeometry,
  createPrismGeometry,
  createRoundedQuadGeometry,
  MeshNode,
} from '@julianagaibler/stargazer'
import type { MeshMaterial } from '@julianagaibler/stargazer'

const ring = createDiscGeometry({ radius: 1, innerRadius: 0.7 })
const post = createPrismGeometry({
  sides: 48,
  radius: 0.3,
  height: 2,
  smooth: true,
})
const panel = createRoundedQuadGeometry({ width: 3, height: 2, radius: 0.2 })

const material: MeshMaterial = { lit: true, color: [0.9, 0.9, 0.9, 1] }
engine.tree.add(new MeshNode(ring, material))
engine.tree.add(new MeshNode(post, material))
engine.tree.add(new MeshNode(panel, material))
```

The ring, the cylinder and the panel appear at the origin. Quads lie in the XY plane and face `+z`, like a sheet held up to the camera. Discs and prisms stand on the XZ plane with `+y` up, like an object on the ground. Rotate the node to place them elsewhere.

One disc builder makes a filled circle, a pie slice, a ring and an arc through `innerRadius` and `sweepAngle`. One prism builder makes a low-poly marker and a smooth cylinder through `sides` and `smooth`. {@link DiscOptions} and {@link PrismOptions} list every option.

For a panel with rounded corners, use `createRoundedQuadGeometry`. The edge stays clean at any scale, and the material can stay `'OPAQUE'`, so the mesh writes depth and casts a correctly shaped shadow. An alpha cutout gives up both.

### Textures from runtime artwork

{@link createTexture} builds the {@link MaterialTexture} that a texture slot takes, from a canvas or an `ImageBitmap`. It puts art that did not come from a glTF file onto a mesh, and it pairs with {@link rasterizeSvg}:

```ts
import {
  MeshNode,
  createQuadGeometry,
  createTexture,
  rasterizeSvg,
} from '@julianagaibler/stargazer'

const canvas = await rasterizeSvg(svgText, { width: 512 })
const tex = await createTexture(canvas) // sRGB and mipmapped by default
const card = new MeshNode(createQuadGeometry({ width: 2, height: 1 }), {
  lit: false,
  color: [1, 1, 1, 1],
  baseColorTex: tex,
})
engine.tree.add(card)
```

The card shows the SVG unshaded, on a 2 by 1 meter quad facing `+z`. See [Assets](/guides/assets) for the options.

### Draw order and transparency

Each frame the renderer draws the opaque and alpha-`MASK` meshes first and writes depth. Within each program they draw nearest first, so the depth test rejects what is hidden behind them. Then it draws `BLEND` meshes from back to front and leaves the depth buffer unchanged.

A mesh's geometry can start as `null`, for example while a model downloads. The renderer draws the mesh once its geometry is set and uploaded. After a GPU context loss, buffers upload again from the geometry the mesh holds.

### glTF details

`loadGltf` reads mesh geometry, the node tree, metallic-roughness materials with their textures, alpha mode, double-sidedness, `KHR_lights_punctual` lights and TRS animations. {@link loadGltf} lists the supported attributes and extensions. Base color and emissive textures load as sRGB, the others as linear data, with mipmaps as the file's sampler asks. The loader computes normals that the file leaves out.

`KHR_materials_transmission` glass draws as a plain translucent blend with no refraction. For an unsupported extension the loader logs a warning once and loads the model with the extension skipped, even when the file lists the extension as required. The loader skips skinning, morph targets, a second UV set and image-based lighting.

{@link parseGltf} is the synchronous core, for tests and custom loaders. It builds the tree and attaches texture descriptors that hold the compressed image bytes, and leaves image decoding and GPU work to the caller. `loadGltf` calls it and then decodes the images with `createImageBitmap`.

### Animation

`loadGltf` reads a model's TRS keyframe animations into {@link AnimationClip} objects. It adds an `AnimationPlayer` under the returned root that plays the first clip in a loop. The player writes the transforms during the update pass, before world matrices are computed, so animated nodes draw in their new pose in the same frame.

```ts
import { AnimationPlayer, loadGltf } from '@julianagaibler/stargazer'

const model = await loadGltf('/models/bird.glb') // already animating
const player = model.children.find(
  (n) => n instanceof AnimationPlayer,
) as AnimationPlayer
player.speed = 0.5
player.pause()
```

The bird holds its current pose, and `resume()` continues at half speed. `speed`, `looping`, `playing` and `time` (the playhead in seconds) are public fields, and `resume(true)` restarts from the first frame. `LINEAR` and `STEP` interpolation are exact, and `CUBICSPLINE` plays as linear between the keyframe values. Each file gets a player for its first clip.

### Lighting

The renderer reads each light's world position and its local `-z` axis every frame, so a light nested under a moving node follows it. {@link Light3D} lists how many lights shade a scene at once.

All lights take `color` (linear RGB) and `intensity`. {@link PointLight3D} and {@link SpotLight3D} take `range`, which fades the light to zero at that distance. A spot light takes `innerConeAngle` and `outerConeAngle`, both half-angles in radians. It is at full brightness inside the inner cone and dark outside the outer cone:

```ts
import { SpotLight3D } from '@julianagaibler/stargazer'

const beam = new SpotLight3D({
  intensity: 20,
  range: 12,
  innerConeAngle: 0.2,
  outerConeAngle: 0.5,
})
beam.transform.setPosition(0, 4, -4)
engine.tree.add(beam)
```

The light shines from 4 units up along `-z`, with a bright core and a soft edge. PBR shading is metallic-roughness Cook-Torrance GGX, plus a constant ambient term. A metal shows highlights from the lights and stays dark elsewhere. glTF point and spot intensities are physical units (candela), so imported lights can look faint. Raise their `intensity` to compensate.

For darkening in contact seams and creases, set `engine.ambientOcclusion.enabled = true`. See [Ambient occlusion](/guides/ambient-occlusion).

### Shadows

Opaque and alpha-`MASK` meshes cast shadows from all three light types, and PBR meshes receive them. A `MASK` mesh casts the shape of its whole geometry, cutout included.

```ts
const lamp = new PointLight3D({
  intensity: 5,
  shadowEnabled: true,
  shadowBias: 0.004,
  shadowOpacity: 0.8,
})
```

`shadowBias` and `shadowNormalBias` move the shadow test off the surface, and `shadowOpacity` lightens the shadow. {@link Light3DOptions} lists the shadow fields with their defaults. A bias that is too small shows shadow acne, where a surface shadows itself in stripes. A bias that is too large detaches a shadow from its caster. The defaults suit meter-scale scenes. Shadows are filtered with a small PCF kernel (several depth samples averaged) for soft edges.

A directional shadow map fits itself to the bounds of all casters. That is sharp for a compact scene. A large ground plane spreads the map thin and blurs nearby shadows, so set a positive `shadowMaxDistance` on the light. It caps the fitted area and keeps resolution on the near scene.

The shadow maps render again when a caster moves or changes geometry, a casting light moves, or a mesh or light is added, removed or hidden. A still scene reuses the maps. {@link Light3D} lists how many lights cast at once.

### Fog

`engine.fog` is a live {@link Fog} object that blends every 3D surface toward a color by its distance from the camera. Use it to fade distant geometry into a horizon or to hide the far clip plane. Fog is off until you enable it, and it applies to flat and PBR meshes:

```ts
import { createEngineHost } from '@julianagaibler/stargazer'

const host = createEngineHost({
  canvas,
  fog: { enabled: true, color: [0.6, 0.7, 0.85], density: 0.05 },
})

host.engine.fog.mode = 'linear' // switch models at runtime
host.engine.fog.start = 8 // clear up close
host.engine.fog.end = 40 // solid fog from this distance
```

Distant meshes fade into a pale blue. The `'exp'` model fades by `1 - exp(-density * distance)` and approaches full fog as the distance grows. The `'linear'` model ramps from `start` to `end` and suits a bounded scene. {@link Fog} lists the fields and defaults. The color is a display-space (gamma) RGB triple, applied after tone mapping, so it shows as the exact color you set.

Fog is a color blend inside the mesh shaders and adds no passes. It tints color and leaves alpha unchanged, so transparent surfaces still blend correctly. The debug views "unshaded" and "normals" skip it. For a screen-space effect such as a vignette, see [Post-processing](/guides/post-processing).

### Render quality

`engine.quality` is a live {@link RenderQuality} object. Set its starting values when you create the host, and change them at any time. The renderer uses a change on the next frame:

```ts
const host = createEngineHost({
  canvas,
  quality: { shadowMapSize: 2048, anisotropy: 8 },
})

host.engine.quality.meshShadowsEnabled = false
```

The shadow maps are 2048 pixels on a side, and the second line drops all shadow passes while lights keep shading. A larger shadow map is sharper and costs more memory and fill. `shadowSoftness` sets the PCF samples per lookup, and more samples soften shadow edges. `adaptive` lets the engine lower quality when the GPU falls behind, one step at a time. {@link RenderQuality} lists the settings, their defaults and the order of the steps. See [Engine setup](/guides/setup).

### Pick by hand

[`screenToRay(ndcX, ndcY)`](/module/camera/cameranode3d#screentoray) builds a world-space ray from a normalized device coordinate, where `x` and `y` run from `-1` to `1` and `y` points up. {@link raycastWorld3D} returns the nearest visible mesh the ray hits and the distance to it:

```ts
import { raycastWorld3D } from '@julianagaibler/stargazer'

const ray = engine.currentCamera3D!.screenToRay(ndcX, ndcY)
const hit = raycastWorld3D(engine.tree, ray)
if (hit) select(hit.node)
```

An optional third argument filters the meshes it tests. Like pointer picking, it tests bounding boxes.

### Releases outside the pressed mesh

The node a pointer goes down on captures it, so `onPointerUp` arrives there wherever the release lands. A 3D button that fires only when the release is still over it checks again on release. [`pick3D(cssX, cssY)`](/module/input/inputsystem#pick3d) runs the same pick as the press, including under the debug fly camera:

```ts
mesh.onPointerUp = (e) => {
  const under = e.stage.input?.pick3D(e.pointer.screen.x, e.pointer.screen.y)
  if (under === mesh) fire()
}
```

For 2D nodes, {@link ButtonBehavior} does this check for you.

### HTML pinned to a 3D node

The {@link domAnchor3d} Svelte action, or `engine.dom.attachWorld3d`, moves an HTML element to a 3D node's position on screen every frame. It hides the element when the node is behind the camera:

```svelte
<div
  use:domAnchor3d={{ engine, node: cube, camera: cam, scaleWithDistance: true }}
>
  <button onclick={fire}>Launch</button>
</div>
```

The button stays upright on screen, centered on the cube, and shrinks as the cube moves away. With `orient: true` the element tilts with the node's surface through a CSS `matrix3d`, and stays aligned with the meshes across the orthographic-to-perspective blend. `pxPerUnit` and `backfaceCull` tune an oriented element, and {@link Dom3DAttachOptions} lists them. The element always draws over the meshes, even when a mesh is in front of the node. See [HTML overlays](/guides/html-overlays) for the container setup.

[`worldToScreen(x, y, z, cssW, cssH)`](/module/camera/cameranode3d#worldtoscreen) is the projection the action uses. It returns CSS-pixel coordinates and a `behind` flag.

### Debugging 3D

The debug HUD (`?debug=hud`, or press `Y`) covers the 3D world. Press `V` for a free fly camera, `O` to outline node bounds including mesh bounding boxes, and `P` to freeze updates and tweens while rendering and the debug camera keep running. The Rendering panel adds 3D views when the scene has 3D content: wireframe, unshaded albedo, world normals and raw ambient occlusion. The Quality panel holds the shadow, ambient occlusion and texture filtering settings.

The Scene panel shows 2D, 3D and group nodes in one tree, and the texture inspector has a "3D models" source that lists every loaded material texture with its role. See [Debugging](/guides/debugging) for the keys and panels.

To check that 3D and stencil strokes coexist, open `?demo=shapes3d`. It draws a translucent multi-segment stroke over a 3D scene. Press `T` to detach and attach the 3D content. The stroke stays one even band in both states. The demo runs on WebGL2 by default and on WebGPU with `?gfx=webgpu`.

### Common problems

The canvas shows no 3D content. The stage has no 3D camera. Add a {@link CameraNode3D} to the tree. The first one added becomes current.

A 3D mesh is hidden behind a 2D shape. The 3D pass runs at the start of the main pass, before the recorded 2D layers, whatever order the nodes are in. To show 2D behind 3D, leave that area of the 2D content empty.

A metal or glass material looks dark or flat. Lighting is analytic: light nodes plus a constant ambient term. Lower `metallicFactor`, or add lights for the surface to catch. Ambient occlusion darkens contact seams, and by default it darkens only the ambient term.

A flat material shows no shadows. Shadows apply to PBR meshes, so set `pbr: true`. A flat material is shaded by the built-in light.

A model shows no second UV set, skin or morph targets. The loader reads `TEXCOORD_0` and plays the first animation clip. {@link loadGltf} lists what it reads.
